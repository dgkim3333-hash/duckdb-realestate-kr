# 부동산 데이터 창고 짓기

**엑셀은 100만 행에서 멈춥니다.** 공시가격 한 파일이 1,558만 행입니다.
그렇다고 데이터베이스 서버를 세우자니 설치·계정·포트가 따라옵니다.

[**DuckDB**](https://duckdb.org)는 그 사이를 메웁니다. 실행 파일 하나, 데이터 파일 하나.
국토부 실거래가·건축물대장·공시가격·경매낙찰을 한 곳에 모아 SQL로 물어보는 방법을 정리했습니다.

> 📄 **[안내서 보기](https://dgkim3333-hash.github.io/duckdb-realestate-kr/)**

## 왜 한 곳에 모으나

따로 있으면 각각은 그냥 목록입니다. 합쳐야 **질문이 됩니다.**

건축물대장에서 *준공 22년 된 다가구*를 고르고 → 실거래가로 그 동네 ㎡단가를 잡고
→ 철도역 좌표로 도보 8분인지 재고 → 경매 낙찰결과로 *이런 물건이 감정가의 몇 %에 떨어지는지*를 봅니다.

네 번의 조회가 아니라 **한 번의 질의**입니다.

## 설치

```
# 윈도우 — duckdb.org/install 에서 zip 받아 압축 풀면 끝
duckdb.exe C:\NPL\npl.duckdb

# 파워셸 한 줄
powershell -NoExit iex (iwr "https://install.duckdb.org/install.ps1").Content

# 파이썬
pip install duckdb
```

현재 버전 **1.5.5**. Microsoft Visual C++ 재배포 패키지가 필요합니다.

## 겪어보고 아는 함정 셋

**① 법정동코드를 리 단위로 쓰지 마십시오.**
읍·면은 리마다 코드가 달라, 평택시 팽성읍 하나에 26개가 붙습니다.
그대로 조인하면 24만 행이 40만 행으로 부풀어 오릅니다.

**② 파일명을 믿지 마십시오.**
국토부 사이트가 과거 조회 결과를 잘못 내려주는 일이 실제로 있었습니다.
파일 안의 검색조건 머리글을 열어 시도·기간·유형을 눈으로 확인하십시오.

**③ 단독과 다가구를 섞지 마십시오.**
대지 ㎡단가가 3.8배 차이납니다. 섞어서 중앙값을 내면 감정가를 3배 넘게 틀리게 잡습니다.

**그리고 경매와 공매를 한 표에 합치지 마십시오.**
저감 구조가 다릅니다 — 경매는 회차당 20~30%, 공매는 1%. 분모가 다른 숫자의 평균은 의미가 없습니다.

## 백업

파일 하나라는 게 장점이자 약점입니다. 다만 원천이 공개 데이터라
다시 받으면 복원됩니다 — 잃는 건 시간입니다.

프로그램이 파일을 붙잡고 있으면 단순 복사는 실패합니다.

```sql
-- 통째로 내보내기 (2.2GB → 415MB)
EXPORT DATABASE 'D:/백업/npl_20260922' (FORMAT PARQUET, COMPRESSION ZSTD);

-- 되살리기
IMPORT DATABASE 'D:/백업/npl_20260922';
```

내보낸 폴더의 `load.sql`에 **절대 경로가 박혀 있습니다.** 다른 PC에서 복원하려면
그 경로를 먼저 치환해야 합니다. 그리고 **백업은 원본과 다른 물리 디스크에** 두십시오.
