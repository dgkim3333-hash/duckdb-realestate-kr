# 부동산 데이터 창고 짓기

**엑셀은 100만 행에서 멈춥니다.** 공시가격 한 파일이 1,558만 행입니다.
열리지도 않습니다. 그렇다고 데이터베이스 서버를 세우자니 설치·계정·포트가 따라옵니다.

[**DuckDB**](https://duckdb.org)는 그 사이를 메웁니다. 실행 파일 하나, 데이터 파일 하나.
국토부 실거래가·건축물대장·공시가격·경매낙찰을 한 곳에 모아 SQL로 물어보는 방법을 정리했습니다.

## 설치 — 5분

### 방법 A · 실행 파일 (윈도우, 가장 쉬움)

[**duckdb.org/install**](https://duckdb.org/install/) 에서 Windows를 고르고
`duckdb_cli-windows-amd64.zip` 을 받습니다.

압축을 풀면 **`duckdb.exe` 하나만 나옵니다.**

**설치 과정이 없습니다 — 그 파일이 곧 프로그램입니다.**
「다음 > 다음 > 완료」도, 레지스트리도, 서비스 등록도 없습니다.
바탕화면에 둬도 되고 USB에 넣고 다녀도 됩니다. 지우고 싶으면 그 파일만 지우면 끝입니다.

```
# 받은 폴더에서 실행
duckdb.exe

# 또는 데이터 파일을 지정해서 열기
duckdb.exe C:\NPL\npl.duckdb
```

Microsoft Visual C++ 재배포 패키지가 필요합니다.
대부분 PC에 이미 깔려 있고, 없으면 실행할 때 알려줍니다.

### 방법 B · 파워셸 한 줄

직접 받기가 번거로우면 이 한 줄이 알아서 내려받아 PATH까지 잡아줍니다.

```
powershell -NoExit iex (iwr "https://install.duckdb.org/install.ps1").Content
```

### 방법 C · 파이썬에서 쓸 사람

```
pip install duckdb
```

파이썬으로 쓰면 pandas와 바로 오갑니다.
CSV를 읽어 테이블로 만들고 결과를 데이터프레임으로 받는 게 몇 줄입니다.

### 첫 명령 세 개

```sql
-- CSV를 읽어 테이블로 만들기 (헤더 자동 인식)
CREATE TABLE 실거래 AS
  SELECT * FROM read_csv('C:/data/아파트매매.csv');

-- 뭐가 들어있나 보기
SELECT * FROM 실거래 LIMIT 10;
DESCRIBE 실거래;

-- 나가기
.quit
```

> **CSV를 미리 정리하지 않아도 됩니다.**
> `read_csv` 가 구분자·인코딩·컬럼 타입을 알아서 잡습니다.
> 한글 CSV가 깨지면 `encoding='utf-8'` 이나 `all_varchar=true` 를 덧붙이면 대개 해결됩니다.
> 파일 여러 개를 `'C:/data/*.csv'` 처럼 한 번에 읽을 수도 있습니다.

현재 버전 **1.5.5**.

## 엑셀과 갈리는 지점

엑셀은 **보면서 고치는** 도구이고, DuckDB는 **쌓아놓고 물어보는** 창고입니다.
둘은 경쟁하지 않습니다. 실제로는 DuckDB에서 조건을 걸어 200행쯤 뽑아낸 뒤,
그걸 엑셀로 열어 보는 식으로 씁니다.

## 왜 한 곳에 모으나

따로 있으면 각각은 그냥 목록입니다. 합쳐야 **질문이 됩니다.**

건축물대장에서 *준공 22년 된 다가구*를 고르고 → 실거래가로 그 동네 ㎡단가를 잡고
→ 철도역 좌표로 도보 8분인지 재고 → 경매 낙찰결과로 *이런 물건이 감정가의 몇 %에 떨어지는지*를 봅니다.

네 번의 조회가 아니라 **한 번의 질의**입니다.

```sql
-- 동네 ㎡단가 중앙값
SELECT 법정동, count(*) AS 건수,
       median(거래금액 / 전용면적)::BIGINT AS ㎡단가
FROM 실거래_아파트_매매
WHERE 시군구 LIKE '%평택시%'
GROUP BY 1 HAVING 건수 >= 10
ORDER BY ㎡단가 DESC;
```

## 겪어보고 아는 함정 셋

**① 법정동코드를 리 단위로 쓰지 마십시오.**
읍·면은 리마다 코드가 달라, 평택시 팽성읍 하나에 26개가 붙습니다.
그대로 조인하면 24만 행이 40만 행으로 부풀어 오릅니다.

**② 파일명을 믿지 마십시오.**
국토부 사이트가 과거 조회 결과를 잘못 내려주는 일이 실제로 있었습니다.
파일 안의 검색조건 머리글을 열어 시도·기간·유형을 눈으로 확인하십시오.

**③ 단독과 다가구를 섞지 마십시오.**
대지 ㎡단가가 3.8배 차이납니다. 섞어서 중앙값을 내면 감정가를 3배 넘게 틀리게 잡습니다.

**그리고 경매와 공매를 한 표에 합치지 마십시오.**
저감 구조가 다릅니다 — 경매는 회차당 20~30%, 공매는 1%. 분모가 다른 숫자의 평균은 의미가 없습니다.

## 백업

파일 하나라는 게 장점이자 약점입니다. 다만 원천이 공개 데이터라
다시 받으면 복원됩니다 — 잃는 건 시간입니다.

프로그램이 파일을 붙잡고 있으면 단순 복사는 실패합니다.

```sql
-- 통째로 내보내기 (2.2GB → 415MB)
EXPORT DATABASE 'D:/백업/npl_20260922' (FORMAT PARQUET, COMPRESSION ZSTD);

-- 되살리기
IMPORT DATABASE 'D:/백업/npl_20260922';
```

내보낸 폴더의 `load.sql`에 **절대 경로가 박혀 있습니다.** 다른 PC에서 복원하려면
그 경로를 먼저 치환해야 합니다. 그리고 **백업은 원본과 다른 물리 디스크에** 두십시오.
같은 디스크면 같이 죽습니다.
